Agent runtime · multi-tenant · human approval gate

theSide.io Intelligence Platform

Each night the platform reads a client's live data (ads, calendar, CRM, search, reviews) and proposes actions. A critic removes the weak ones. A deterministic ranker orders what survives, and an operator approves. Approved actions run through one of nine connectors. The result is measured 7, 14 and 28 days later, and what was learned is written back as memory the next run reads.

9connectors (ads, CRM, calendar, search, reviews, practice management)
32tables in one schema, every row scoped to its tenant
7/14/28day outcome attribution on every approved action
Proposer (forced structured output) Critic Ranker (deterministic) Supervisor → human approves Execute with an idempotency claim, signed audit row

My role: I defined the product, the agent roles, the data model, the approval and service-tier model, and the acceptance criteria. I directed the build, reviewed the diffs and tested the flows. It is built and tested (0 TypeScript errors, 0 ESLint findings across 369 files, 21 test groups passing in the June 2026 automated audit); it has not yet run against a client account.

Autonomous engine · runs nightly · ships its own code

Nightshift and the Side Studios engine

A 19-node LangGraph state graph runs at 08:23 UTC. It crawls theside.studio and runs nine analyzer categories. It sweeps 20 positioning queries against ChatGPT to record who gets cited, then scores two separate grades. It drafts one page through writer, designer, illustrator and brand-QA nodes, with a bounded revision loop. A decision layer then picks up to three missions, dispatches AI coding agents in their own worktrees, verifies them, and lands them by trust class. I can revert anything, and the console has no approve button.

29missions in the last 7 nights: 23 landed, 4 staged for me, 2 unresolved
$45 / $250hard caps per night and per week, in a policy file the engine cannot edit
Sense: crawl, analyze, measure citations Decide: ≤3 missions by weight × evidence Do: agent in a worktree, verifier re-runs the gates Land by class: A same night, B after canary, C waits for me

My role: I wrote the spec and the trust ladder, set the budgets and the gates, directed the build, and read it every morning. It runs on our own site first; client sites are enabled one at a time behind the same gates. The walkthrough shows what it shipped and what it cost.

A revenue system, through three technology generations

The system that taught me why gates matter. Built for pre-construction real-estate agents in 2020-21, before generative AI.

Revenue system · pre-construction real estate

From first touch to transaction

Project-marketing firms served developers. Nothing served the agent. I designed the acquisition-to-close system that filled that gap: acquire, capture, prequalify, nurture, route, close, with the CRM orchestrating every step. The conversation layer was a rule-based workflow first, and it grew from 50 branches to more than 120. In-house NLU models replaced it, trained on transcripts from 8,000 captured SMS and web-chat turns. LLM agents carry it now.

1,000+buyer conversations handled a day
1% → 3%lead-to-transaction conversion
~$45Myear-one transaction value (transactions closed, not revenue)
Rule-based conversation workflows In-house NLU on proprietary data LLM agents

My role: I found the gap and defined the business model and the customer journey. I designed the funnel and the CRM logic, directed the team through each transition, and productized the service into a subscription agents could buy. Our engineering team built the models; I owned what they had to do.

How I work

Outcome first. I own the system and the result; AI coding agents are how the implementation gets done.

Define first: the operating model, the agent roles, the data flows, and what "correct" means, written down before anything is built. Then direct: Claude Code and Codex do the implementation in worktrees against those criteria, and I read the diffs and run the tests. Gate by class of change: a human approves where money moves, trust classes decide elsewhere, and budgets live in files the agents cannot edit. Measure: every approved action is checked against what happened 7, 14 and 28 days later.

Building revenue and AI systems since 2012, as a founder and as an advisor. What I want next is one product to own, from the build to the market.
